# ARCHITECTURE.md — TabletTime

## Tech stack
- Kotlin only
- Jetpack Compose, Material 3
- MVVM (ViewModel + StateFlow)
- Room (local database — reminders + snooze state)
- `AlarmManager` + `BroadcastReceiver` for scheduling and triggering
- `NotificationManager` with full-screen intent for the alarm trigger UI
- No networking libraries, no Firebase, no third-party analytics/ad SDKs

## App identity
- App name: **TabletTime**
- Package name: `com.poshan.tablettime`
- Min SDK: 26 (Android 8.0) — needed for reliable notification channels
- Target/compile SDK: latest stable at build time

## Folder structure

```
app/
 └── src/main/java/com/poshan/tablettime/
      ├── MainActivity.kt
      ├── ui/
      │    ├── home/HomeScreen.kt          (master on/off switch, list of reminders)
      │    ├── setup/AddReminderScreen.kt  (time picker, label, days)
      │    ├── checkin/CheckInActivity.kt  (full-screen yes/no alarm screen)
      │    ├── theme/ (Color.kt, Type.kt, Theme.kt)
      │    └── components/ (reusable buttons, cards)
      ├── data/
      │    ├── Reminder.kt (Room entity)
      │    ├── ReminderDao.kt
      │    └── AppDatabase.kt
      ├── alarm/
      │    ├── AlarmScheduler.kt   (schedules/cancels exact alarms)
      │    ├── AlarmReceiver.kt    (BroadcastReceiver, fires on trigger time)
      │    └── BootReceiver.kt     (re-schedules alarms after reboot)
      └── viewmodel/
           ├── HomeViewModel.kt
           └── ReminderViewModel.kt
```

## Permissions required
- `SCHEDULE_EXACT_ALARM` (Android 12+)
- `POST_NOTIFICATIONS` (Android 13+)
- `RECEIVE_BOOT_COMPLETED` (to re-register alarms after reboot)
- Optional: full-screen intent permission / battery-optimization exemption request, with an in-app explanation before asking
